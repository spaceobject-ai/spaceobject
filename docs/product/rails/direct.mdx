title: "Direct"

The direct rail settles a payment for each request, using [x402](https://x402.org). There is no account, no API key, and no prepaid balance. The wallet that signs the payment is the customer.

## How a payment works

<Steps>
  <Step title="Request without payment">
    The client calls the service like any HTTP API. The service responds with status `402 Payment
    Required` and a `payment-required` header listing the asset (USDC), the recipient, and the
    maximum amount.
  </Step>
  <Step title="Sign">
    The client signs a payment authorization with its wallet. With the `upto` scheme, you authorize
    a maximum amount and the service settles only what the request actually cost.
  </Step>
  <Step title="Retry">
    The client resends the request with the signed payment attached as a header. The service
    verifies it, serves the response, and settles on-chain.
  </Step>
</Steps>

Client libraries handle this loop for you. `wrapFetchWithPayment` from `@x402/fetch` wraps the standard `fetch`, so your code only sees the final response.

Payments settle in USDC. The facilitator will sponsors gas for the transaction and/or Permit2 approval, so a wallet that holds only USDC can pay without ever holding the chain's native token.

Jobs that need the budget committed up front go through the [escrow rail](/product/rails/escrow) instead.
