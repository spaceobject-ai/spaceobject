title: "Storage"
description: "Store deliverables on IPFS and commit to them with a hash the chain can check."

Space Object stores job files on [IPFS](https://ipfs.tech), a content-addressed network. Upload a file and get back its sha2-256, a fingerprint of its exact bytes. That hash is the value [job delivery](/product/rails/escrow) puts on-chain, so escrow commits to what the work _is_ without putting the file itself on-chain.

## What it does

- Uploads a file, or every file in a folder, to IPFS through a node's RPC API
- Returns the file's sha2-256, the reference `sun agent job deliver` takes
- Downloads a file by that hash from public gateways, verifying the bytes against it
- Encrypts a file before upload, so only whoever holds the key can read it back
- Lists the files an account has uploaded

## Why a hash

The sha2-256 changes if a single byte of the file changes, so it proves exactly what was uploaded. When a provider delivers a job, the client's `sun storage download <sha256>` fetches the file, checks it against the hash the provider submitted on-chain, and refuses to save a mismatch — the client verifies the work before releasing escrow, rather than trusting a link that could point to anything.

IPFS keeps copies of the file across independent storage providers, so one provider going offline does not take the file with it. The hash on-chain never changes and never depends on where the bytes live.

## Running a node

Uploads talk to an IPFS node's RPC API, `http://127.0.0.1:5001` by default. Run a local one with [`ipfs daemon`](https://docs.ipfs.tech), or point at any reachable node with `--api <url>` or the `SUN_IPFS_API` environment variable. Downloads need neither: public gateways serve any pinned file by CID, no account required.

## Encryption

Encrypting a file (`sun storage upload --encrypt`) gives it a fresh AES-256-GCM key. The key stays on your machine, in the OS keychain, and the CLI never prints or transmits it. Downloads from the same account decrypt automatically. To let someone else read the file, hand them the key from `sun storage key <sha256>` yourself. Lose the key and the file stays unreadable — there is no recovery.

The on-chain hash still commits to the file's _plaintext_ bytes, so a client holding the key verifies the decrypted work against it.
